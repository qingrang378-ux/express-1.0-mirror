# 快递公司异常处理系统 (Express Exception Handling) - 用户故事与验收标准清单

## 模块 1: 运单与轨迹查询 (Waybill & Tracking)

### US-01: 客户查询属于自己的模拟运单
> **As a** 运单所属客户  
> **I want to** 输入运单号查询该运单的基本信息与运输轨迹  
> **So that** 我能了解包裹当前状态并判断是否需要发起异常反馈。

* **AC 1.1 (正常流 - 查询自己的运单)**:
  - **Given**: 客户已登录，且系统中存在属于该客户的运单；
  - **When**: 客户输入该运单号并点击查询；
  - **Then**: 系统展示运单基本信息与按时间顺序排列的运输轨迹。

* **AC 1.2 (异常流 - 运单不存在)**:
  - **Given**: 客户已登录；
  - **When**: 客户查询一个系统中不存在的运单号；
  - **Then**: 系统不展示运单详细信息，并返回统一模糊提示：“运单不存在或无权查看”。

* **AC 1.3 (安全约束 - 运单不属于当前客户)**:
  - **Given**: 客户已登录，且系统中存在属于其他客户的运单；
  - **When**: 当前客户查询该运单号；
  - **Then**: 系统不展示发件人、收件人、轨迹、异常记录等详细信息，并返回统一模糊提示：“运单不存在或无权查看”。

## 模块 2: 异常反馈提交 (Exception Feedback)

### US-02: 客户对异常运单提交反馈
> **As a** 运单所属客户  
> **I want to** 选择异常类型并填写异常描述后提交反馈  
> **So that** 客服能够介入处理我的异常问题。

* **AC 2.1 (正常流 - 提交异常反馈)**:
  - **Given**: 客户已查询到属于自己的运单；
  - **When**: 客户选择异常类型并填写异常描述后提交；
  - **Then**: 系统创建一条异常反馈记录，状态为 `PENDING_ACCEPT`，并关联该运单与当前客户。

* **AC 2.2 (数据约束 - 异常类型枚举)**:
  - **Given**: 客户正在填写异常反馈表单；
  - **When**: 客户展开异常类型选项；
  - **Then**: 可选类型至少包括：延误、物品破损、订单标签破损、联系人异常、签收争议。

* **AC 2.3 (异常流 - 无权运单提交反馈)**:
  - **Given**: 客户已登录；
  - **When**: 客户尝试对不属于自己的运单提交异常反馈；
  - **Then**: 系统拒绝提交，不创建异常反馈记录，并返回统一模糊提示：“运单不存在或无权查看”。

---

## 模块 3: 异常工单创建与分派 (Ticket Creation & Assignment)

### US-03: 客服创建异常工单并分派运营
> **As a** 客服人员  
> **I want to** 根据客户异常反馈创建工单、分类并分派给运营人员  
> **So that** 异常进入内部处理流程并明确责任人。

* **AC 3.1 (正常流 - 创建工单)**:
  - **Given**: 存在一条状态为 `PENDING_ACCEPT` 的异常反馈；
  - **When**: 客服点击“创建工单”；
  - **Then**: 系统生成工单号，关联原异常反馈与运单，工单初始状态为 `PENDING`，并根据异常类型设置处理期限。

* **AC 3.2 (数据约束 - 工单分类)**:
  - **Given**: 客服正在创建工单；
  - **When**: 客服选择异常分类；
  - **Then**: 工单保存该分类，并用于后续 SLA 计算与统计。

* **AC 3.3 (状态机流转 - 分派运营)**:
  - **Given**: 工单状态为 `PENDING`；
  - **When**: 客服选择一名运营人员并确认分派；
  - **Then**: 工单记录被分派人员 `assigneeId`，该运营人员可在自己的待办列表中看到该工单。

## 模块 4: 运营受理与内部处理 (Operations Handling)

### US-04: 运营受理被分派工单
> **As a** 运营人员  
> **I want to** 受理被分派给我的异常工单  
> **So that** 我能开始核实与处理。

* **AC 4.1 (正常流 - 查看待办)**:
  - **Given**: 运营已登录，且存在分派给该运营的 `PENDING` 工单；
  - **When**: 运营进入待处理列表；
  - **Then**: 系统仅展示分派给该运营的工单，不展示分派给其他运营的工单。

* **AC 4.2 (状态机流转 - 受理工单)**:
  - **Given**: 工单状态为 `PENDING`，且当前运营是工单的被分派人员；
  - **When**: 运营点击“受理”；
  - **Then**: 工单状态变为 `PROCESSING`，系统记录受理时间与操作人。

* **AC 4.3 (安全约束 - 非被分派人员不能受理)**:
  - **Given**: 工单已分派给其他运营；
  - **When**: 当前运营尝试受理该工单；
  - **Then**: 系统拒绝操作，工单状态保持不变。

---

### US-05: 运营记录核实过程并提交处理结果
> **As a** 运营人员  
> **I want to** 记录核实过程并提交处理方案和结果  
> **So that** 客服可以据此生成对外反馈。

* **AC 5.1 (正常流 - 记录内部核实过程)**:
  - **Given**: 工单状态为 `PROCESSING`，且当前运营是工单的被分派人员；
  - **When**: 运营填写内部核实记录并保存；
  - **Then**: 系统保存该记录，标记为 `internal_only`，客户页面不展示该记录。

* **AC 5.2 (状态机流转 - 提交处理结果)**:
  - **Given**: 工单状态为 `PROCESSING`，且当前运营是工单的被分派人员；
  - **When**: 运营提交处理方案和处理结果；
  - **Then**: 系统保存内部处理结果，工单状态变为 `PENDING_CS_CONFIRM`，并记录提交时间与操作人。

* **AC 5.3 (安全约束 - 非被分派人员不能提交结果)**:
  - **Given**: 工单状态为 `PROCESSING`，且当前运营不是工单的被分派人员；
  - **When**: 当前运营尝试提交处理结果；
  - **Then**: 系统拒绝操作，工单状态保持不变。

---

## 模块 5: 客服对外反馈 (Customer-Facing Feedback)

### US-06: 客服确认对外说明并反馈客户
> **As a** 客服人员  
> **I want to** 在运营提交结果后确认对外说明  
> **So that** 客户能够看到经过审核的公开进度。

* **AC 6.1 (正常流 - 查看运营处理结果)**:
  - **Given**: 工单状态为 `PENDING_CS_CONFIRM`；
  - **When**: 客服查看工单详情；
  - **Then**: 客服可以看到运营提交的内部处理结果与内部核实记录。

* **AC 6.2 (状态机流转 - 生成对外反馈)**:
  - **Given**: 工单状态为 `PENDING_CS_CONFIRM`；
  - **When**: 客服填写对外说明并确认；
  - **Then**: 系统保存对外反馈记录，标记为 `customer_visible`，工单状态变为 `PENDING_CUSTOMER_CONFIRM`。

* **AC 6.3 (安全约束 - 内部备注不展示给客户)**:
  - **Given**: 工单存在内部备注或内部核实记录；
  - **When**: 客户查看工单公开进度；
  - **Then**: 客户只能看到 `customer_visible` 的说明，不能看到内部备注、内部核实记录与内部处理方案。

---

## 模块 6: 客户确认与重新打开 (Customer Confirmation & Reopen)

### US-07: 客户查看公开进度并确认结果
> **As a** 运单所属客户  
> **I want to** 查看工单公开进度并确认或不认可处理结果  
> **So that** 我能决定是否接受处理方案。

* **AC 7.1 (正常流 - 查看公开进度)**:
  - **Given**: 客户是工单关联运单的所属客户；
  - **When**: 客户查看工单详情；
  - **Then**: 系统展示客户可见的沟通记录与对外反馈，不展示内部记录，并展示当前工单状态与处理时限。

* **AC 7.2 (状态机流转 - 确认结果并关闭)**:
  - **Given**: 工单状态为 `PENDING_CUSTOMER_CONFIRM`，且当前客户是工单所属客户；
  - **When**: 客户确认处理结果；
  - **Then**: 工单状态变为 `CLOSED`，系统记录关闭时间与操作人，该工单不能被重复关闭。

* **AC 7.3 (状态机流转 - 不认可并重新打开)**:
  - **Given**: 工单状态为 `PENDING_CUSTOMER_CONFIRM`，且当前客户是工单所属客户；
  - **When**: 客户选择不认可并申请继续处理；
  - **Then**: 工单状态变为 `PENDING`，系统保留原处理记录、沟通记录、状态日志，并新增一条客户不认可的沟通记录与状态变更日志。

---

## 模块 7: 处理时限与超时标记 (SLA & Timeout)

### US-08: 系统根据处理期限标记超时状态
> **As a** 系统  
> **I want to** 根据处理期限标记工单超时状态  
> **So that** 客服和运营能够及时处理异常工单。

* **AC 8.1 (正常流 - 设置处理期限)**:
  - **Given**: 客服创建工单；
  - **When**: 系统保存工单；
  - **Then**: 系统根据异常类型设置 `deadlineAt`，并设置 `warningAt` 作为即将超时时间。

* **AC 8.2 (状态标记 - 即将超时)**:
  - **Given**: 当前时间已到 `warningAt` 且未到 `deadlineAt`；
  - **When**: 系统展示或查询工单；
  - **Then**: 工单超时状态为 `WARNING`（即将超时），并在客服端和运营端显示明确提示。

* **AC 8.3 (状态标记 - 已超时)**:
  - **Given**: 当前时间已超过 `deadlineAt`；
  - **When**: 系统展示或查询工单；
  - **Then**: 工单超时状态为 `OVERDUE`（已超时），并在客服端和运营端显示明确提示。

---

## 模块 8: 沟通记录与处理留痕 (Communication & Audit Trail)

### US-09: 一个未关闭异常可以多次沟通
> **As a** 客服、运营或客户  
> **I want to** 在一个未关闭工单下进行多次沟通  
> **So that** 完整记录处理过程。

* **AC 9.1 (正常流 - 多次沟通)**:
  - **Given**: 工单未关闭；
  - **When**: 客服、运营或客户新增沟通记录；
  - **Then**: 系统保存多条沟通记录，每条记录包含角色、可见性、内容、时间。

* **AC 9.2 (状态约束 - 不能重复关闭)**:
  - **Given**: 工单状态为 `CLOSED`；
  - **When**: 任意角色尝试再次关闭该工单；
  - **Then**: 系统拒绝重复关闭，不产生新的关闭记录。

* **AC 9.3 (状态机流转 - 重新打开后继续沟通)**:
  - **Given**: 客户不认可处理结果，工单重新进入 `PENDING`；
  - **When**: 客服或运营继续处理并新增沟通；
  - **Then**: 新沟通记录追加在原记录之后，原记录不被删除或覆盖。

---

### US-10: 内部记录与客户可见说明分离
> **As a** 系统  
> **I want to** 将内部处理记录与客户可见说明分开保存  
> **So that** 防止内部信息泄露给客户。

* **AC 10.1 (数据约束 - 内部记录保存)**:
  - **Given**: 运营填写内部核实记录或内部处理结果；
  - **When**: 系统保存记录；
  - **Then**: 记录标记为 `internal_only`。

* **AC 10.2 (数据约束 - 客户可见说明保存)**:
  - **Given**: 客服确认对外说明；
  - **When**: 系统保存记录；
  - **Then**: 记录标记为 `customer_visible`。

* **AC 10.3 (安全约束 - 客户接口过滤)**:
  - **Given**: 客户请求工单详情；
  - **When**: 系统返回数据；
  - **Then**: 只返回 `customer_visible` 的记录，不返回 `internal_only` 的记录。

---

### US-11: 全部处理过程可追溯
> **As a** 客服主管或系统审计者  
> **I want to** 查看工单全部处理过程  
> **So that** 能够追溯责任与处理历史。

* **AC 11.1 (数据约束 - 状态变更日志)**:
  - **Given**: 工单发生状态变更；
  - **When**: 系统保存状态变更；
  - **Then**: 记录 `fromStatus`、`toStatus`、操作人、原因、时间。

* **AC 11.2 (正常流 - 操作记录可追溯)**:
  - **Given**: 工单发生受理、核实、提交结果、对外反馈、客户确认、重新打开等操作；
  - **When**: 查看工单历史；
  - **Then**: 系统展示完整操作记录，并按时间顺序排列。

* **AC 11.3 (状态机流转 - 重新打开保留原记录)**:
  - **Given**: 客户不认可处理结果；
  - **When**: 工单重新打开；
  - **Then**: 原处理记录、沟通记录、状态日志全部保留，新处理过程追加在原记录之后。

## 核心验收场景映射

| 核心验收场景 | 对应用户故事 |
|---|---|
| 1. 客户能够查询自己的模拟运单并提交异常反馈 | US-01、US-02 |
| 2. 客服创建工单后，指定运营人员能够受理 | US-03、US-04 |
| 3. 超过处理期限的工单出现明确提示 | US-08 |
| 4. 内部备注不会出现在客户页面 | US-05、US-06、US-10 |
| 5. 运营提交结果后，由客服生成对外反馈 | US-05、US-06 |
| 6. 客户不认可结果时可以重新打开，全部处理过程可追溯 | US-07、US-09、US-11 |
